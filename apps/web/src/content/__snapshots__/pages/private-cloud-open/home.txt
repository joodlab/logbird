Send your first event

pre|   -H "Authorization: Bearer $LOGBIRD_INGEST_KEY" \
pre|   -H 'Content-Type: application/json' \
pre|   -d '{"action":"booking.cancelled"}'
That's a valid event. Only action is required.
Customer-facing audit logs
Show each customer their own history.
Your customers' admins want to see who did what in their account. Send each event with the customer account it belongs to (tenant), and your product can show every account its own trail.
Viewer tokens. Your server mints a token for one customer account and hands it to the browser. It expires after 15 minutes by default, one hour at most.
Enforced by Logbird. The scope applies outside every query, on search, event detail, counts and export. Nothing in the query can widen it.
Scoped server keys. A scoped read key reads one customer account's events. It can also be limited to events that name one record, to actions with given prefixes, or both.
The limit: One customer account per scope, matched on the id Logbird stored. How it is enforced

Compliance evidence
Answer the auditor with evidence.
When an auditor or a customer's security team asks what happened, show them the events: who acted, for whom, on which records, and what changed.
What a match shows: Matching the file's SHA-256 and size to the export's completed record shows that the file you hold is the file Logbird produced for that export, not that the events were never changed before the export ran, and not who saved the file or when.

[aria-hidden] What you can show
[aria-hidden] The limit
[sr-only: What you can show: ] Each event can name the actor, the staff member acting for them (impersonator), the customer account, the records, and the before and after values of up to 256 changes.
[sr-only: The limit: ] Logbird records what your code sends. It can't add an actor or a change that your event leaves out.
[sr-only: What you can show: ] Retention per project, from 7 days to 10 years. Expired events are permanently deleted every hour.
[sr-only: The limit: ] An owner or admin can shorten retention at any time, and the deletion starts right away. There is no retention lock or legal hold yet.
[sr-only: What you can show: ] The evidence export (jsonl-evidence) carries every matching event with its original payload. When the export completes, its record keeps the filter, the fixed query clock, the SHA-256, the size and the row count, so a file can be matched to its record.
[sr-only: The limit: ] Matching the file's SHA-256 and size to the export's completed record shows that the file you hold is the file Logbird produced for that export, not that the events were never changed before the export ran, and not who saved the file or when.
[sr-only: What you can show: ] Workspace activity records what your team does in Logbird: project and retention changes, keys, members and roles, saved views, invite links, exports, sign-ins, sign-outs and revoked sessions.
[sr-only: The limit: ] It doesn't record who searched or opened events.

For developers
One call per action. No schema to migrate.
Only an action string is required, and each event must fit the ingest limits. Add the fields you have: who did it, in which customer account, to which records, what changed. Logbird lifts the fields it knows into their own columns. Custom top-level fields and anything under metadata are searchable as attributes within the indexing limits, and the full parsed event is available as JSON. Recommended fields are optional: an event is never rejected for missing them.
TypeScript SDK with batching, retries and an explicit flush and shutdown.
Middleware for Hono, TanStack Start and Nuxt; a Vue read composable.
jobAudit for queue workers: the job keeps the original actor and joins the request's operation.
A conformance score on every event: the share of nine recommended checks it passes. The setup page shows which fields your events miss.
Not on TypeScript? Any language that can POST JSON over HTTP works. A .NET package is in the repository and not yet on NuGet: sdks/dotnet, once the source opens.

Route
Worker
pre| // Route (Hono)
pre| app.post('/bookings/:id/cancel', async (c) => {
pre|   const id = c.req.param('id');
pre|   // ...cancel the booking
pre|   const eventId = c.var.audit('booking.cancelled', {
pre|     targets: [{ type: 'booking', id }],
pre|     changes: [
pre|       { field: 'status', before: 'confirmed', after: 'cancelled' },
pre|     ],
pre|   });
pre|   const carrier = await c.var.audit.carrier({ parentEventId: eventId });
pre|   await refunds.add('refund', { bookingId: id, carrier });
pre|   return c.json({ ok: true });
pre| });
The actor is Lina on both events. The worker only carried it out.

Guarantees and limits
What Logbird promises, and where the promise ends.
[aria-hidden] We guarantee
[aria-hidden] The limit
[sr-only: We guarantee: ] A 202 lists accepted event IDs in ids and rejected events in rejected.
[sr-only: The limit: ] Delivery is at least once when the client retries unsettled events, as the SDK does. An exact retry with the same valid, non-blank string id is stored once while the project retains the event; changed content under that id is rejected with duplicate_id_conflict. An event sent without an id gets a new one on every retry.
[sr-only: We guarantee: ] The SDK batches and retries for you.
[sr-only: The limit: ] Its queue is in memory and bounded: a crash before the server acknowledges, or an outage long enough to fill the queue, can lose pending events.
[sr-only: We guarantee: ] Only an action string is required, and each event must fit the ingest limits.
[sr-only: The limit: ] Each event is checked on its own: rejected events are listed in rejected with a reason. On 202, the rest of the batch is accepted. When a 503 lists the unsettled events, retry only those; otherwise retry the whole batch with the same ids.
[sr-only: We guarantee: ] Retention deletes expired events for good.
[sr-only: The limit: ] There's no archive and no undo.
[sr-only: We guarantee: ] Import history by sending events with their original occurredAt, up to 3650 days back.
[sr-only: The limit: ] An older occurredAt is stored at receive time with a warning, and project retention still applies to imports. Logbird doesn't rebuild history from your database.
