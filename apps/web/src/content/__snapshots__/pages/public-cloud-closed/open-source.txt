The product is MIT-licensed: the API, the console, the retention worker, the SDK and the integrations, all in one repository. You can read the code, run it, change it and ship it in your own product. Experimental folders may carry their own licence; each one says so.

[sr-only] What each folder of the Logbird repository contains
Path
What it is
apps/server
The API: ingest and read on /v1, the console API on /api, OpenAPI and a Scalar reference. Hono on Node.
apps/app
The console. TanStack Start and React.
apps/worker
The retention worker: hourly purges and housekeeping. BullMQ on Redis or Dragonfly.
apps/email
Previews for the sign-in and invitation email templates.
packages/contracts
The API's request and response schemas. The source of truth for the API.
packages/clickhouse
ClickHouse client, migrations, query builder and query-language parser.
packages/database
Postgres schema (Prisma): workspaces, projects, keys, saved views.
packages/auth
Email one-time-code sign-in and workspaces, on better-auth.
packages/sdk
@logbird/sdk: the TypeScript client. No dependencies.
packages/integrations/*
@logbird/hono, @logbird/tanstack-start, @logbird/vue, @logbird/nuxt.
packages/ui
The console's design system.
packages/seed
A generator of fictional hotel-booking data, sent through the public API.
examples/*
Small runnable examples for each integration.

Contributing
How to contribute.
Contributions follow CONTRIBUTING.md. In short: Node 22.18+ and pnpm, focused branches, Conventional Commits, and pull requests that explain what changed, why, and how it was verified. UI changes include screenshots. Tests use fictional data only. Maintainers merge.
Node 22.18+ and pnpm
Focused branches and Conventional Commits
Pull requests that explain what changed, why, and how it was verified
Screenshots for UI changes
Fictional data only in tests
Maintainers merge
API changes start in packages/contracts. The server and console change in the same pull request.
GitHub Actions runs the checks on every pull request and push to master. A v* tag builds the release images for amd64 and arm64 and publishes them to GHCR.
Code of conduct
Be kind and constructive.
The project follows the Contributor Covenant, version 2.1. Report conduct issues through the private channel described in SECURITY.md.
Security reports
Found a vulnerability? Tell us privately.
Don't open a public issue. Email security@example.test. Include the affected version, a reproduction with fictional data, and the impact. We coordinate the fix and the disclosure with you privately. We don't offer a response-time SLA yet.

Where the project is today.
The supported line is 0.2, and the latest release is 0.2.1, with Docker images on GHCR for amd64 and arm64. The SDK and the integrations share the platform's version. They aren't on npm yet: use them from source.
