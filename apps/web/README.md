# Logbird web foundation

The marketing workspace is `@logbird/web`. Page bodies intentionally contain one placeholder heading and sentence. Reuse `@logbird/ui` for the design pass.

## Local commands

Use Node 22.18+ and pnpm 10.30.3. From the repository root:

```sh
pnpm install
pnpm --filter @logbird/web typecheck
pnpm --filter @logbird/web test
pnpm --filter @logbird/web dev
```

Dev, preview and start use **4620** exclusively. `preview` aliases the built Node server (`start`). No console, API, database, Redis or ClickHouse service is needed. Before builds or browser checks, verify at least 8 GB free RAM and 40 GB free on <local-path>. Run builds sequentially, never a root build.

```powershell
(Get-CimInstance Win32_OperatingSystem).FreePhysicalMemory/1MB
(Get-PSDrive C).Free/1GB
pnpm --filter @logbird/web build
pnpm --filter @logbird/web preview
```

Dev/build/OG/start load the root `.env` with `dotenv -e ../../.env --`; existing environment variables win. A new Git worktree may lack that gitignored file. Supply the environment before SMTP verification. Tests need no SMTP service and use temporary files. Never commit credentials.

## Routes and static output

`src/lib/site-map.ts` owns routes, navigation, footer groups, descriptions, OG slugs, discovery and the explicit prerender list. Every route calls `pageHead()` with its manifest entry. Add routes and manifest entries together; the parity test checks both directions. `routeTree.gen.ts` is committed, matching the console convention, and regenerated by TanStack's Vite plugin.

TanStack Start prerenders with link crawling, concurrency one and `failOnError: true`. Eighteen public pages plus `/blog/draft` are explicit targets. The draft is `noindex` and excluded from the sitemap. Future published posts need concrete paths and article metadata before indexing. An auxiliary `/404` manifest entry reuses the root not-found component and renders to **`404.html`** via `outputPath`. This gives prerender a successful source response while unknown Node routes still return HTTP 404 through the root component. Cloudflare Assets uses `not_found_handling: "404-page"`.

The discovery Vite plugin emits static `sitemap.xml`, `robots.txt`, `llms.txt` and `_headers`. Canonicals and JSON-LD use the same configuration as discovery and OG generation. Home emits Organization, WebSite and SoftwareApplication; other pages emit breadcrumbs. The only price is the zero-price self-host offer. There are no third-party scripts or trackers; fonts are local through the UI stylesheet.

## Configuration

All provisional domain defaults live only in **`src/env.ts`**. A domain-literal regression test covers `src` and `scripts`. Vite exposes only the four public settings. SMTP values are server-only and never inlined in client code. Set public values before building: prerendered HTML is deployment output.

| Setting | Purpose |
| --- | --- |
| `SITE_URL` | Canonical origin, sitemap, OG host, JSON-LD and Cloudflare form origin |
| `APP_URL` | Console sign-in URL |
| `GITHUB_URL`, `GITHUB_PUBLIC` | Repository link; hidden until explicitly public |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | Optional Node notifications; local Mailpit normally uses port 1025 |
| `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | Server-only optional auth and sender |
| `WAITLIST_NOTIFY_TO` | Server-only notification recipient |

`copy-flags.ts` contains the single generic design-partner line. The named variant is not implemented.

## Waitlist and contact

`POST /api/waitlist` accepts JSON or URL-encoded forms, validates with zod, caps the actual UTF-8 stream at 8 KB and checks a supplied Origin. Optional name/company are capped at 200 characters, message at 2000. Interest is required. The website honeypot acknowledges without persistence or email. The memory limiter allows five requests per IP per minute, **per process/isolate**, using the socket address or Cloudflare-provided client IP. It is best effort, not a shared global limit.

JSON errors have `{ error: { code, message, details? } }` and status 400/413/415/429/503. Native form posts redirect 303 to `/contact?status=ok|error` with the corresponding `#waitlist-ok` or `#waitlist-error` fragment. Static HTML cannot branch on query parameters without a runtime; the fragment reveals a CSS `:target` confirmation inside `noscript`. Fetch enhancement provides field errors and live status, including the unavailable-deployment mailto fallback.

Node appends `.data/waitlist.jsonl` and sends a plain-text notification when SMTP is configured. No auto-reply is sent. If notification fails after append, the endpoint returns 503 and preserves the record; retries can create another record. Real Node deployments need persistent disk and backups. The clean script deliberately preserves `.data`.

Cloudflare returns `waitlist_unavailable` until `WAITLIST_KV` is configured. A typed adapter and commented binding are provided. KV stores a JSON record per submission and does not send email. Configure and verify it before opening the Cloudflare waitlist. No third-party forms/email service is added.

## Media and OG

```sh
pnpm --filter @logbird/web media
pnpm --filter @logbird/web og
```

Both run before build. The media manifest lists eight inspected screenshot pairs/singles with dimensions and factual alt text, plus two clips/posters. Media generation checks missing sources and LFS pointers, validates dimensions and emits AVIF/WebP at 640, 1024 and 1600 px clamped to original width, plus copied WebM and WebP posters. Run `git lfs pull` if a source is a pointer.

`<Screenshot id sizes priority />` uses CSS `.dark`, independent of OS preference. Images have intrinsic dimensions, async decoding and lazy loading; priority images are eager with high fetch priority. `<Clip id />` autoplays only in view with no reduced-motion preference and provides a visible pause/play control. It uses no preload and disconnects its observer on unmount.

OG generation uses Satori, Resvg, local Geist Regular/SemiBold, Geist Mono, IBM Plex Sans Arabic and the outlined bilingual SVG. It emits one 1200×630 PNG per manifest slug under `public/og`. Generated media/OG outputs are ignored. The home sample is copied to **`.tmp/og-home.png`**. The requested `marketing/captures/2026-11-07-web-foundation/og-home.png` lies outside the strict task boundary; the owner can copy the generated sample there for LFS capture.

## Cloudflare Workers deployment (manual)

```sh
pnpm --filter @logbird/web build:cloudflare
cd apps/web
npx wrangler deploy --config wrangler.jsonc
```

`build:cloudflare` sets `NITRO_PRESET=cloudflare-module`; default build selects `node-server`. Both use **`.output/public/`** for assets and **`.output/server/index.mjs`** for runtime. The committed Wrangler config pins `logbird-web`, date `2026-10-01`, `nodejs_compat`, ASSETS, and API-only worker-first routing. Nitro deployment-config generation is disabled so this configuration is authoritative. There is no CI/deploy automation and implementation does not deploy.

The Cloudflare script runs two sequential phases: TanStack prerender through Node, then Worker packaging with prerender disabled only for that second phase. It snapshots the generated HTML, verifies every referenced hashed asset exists in the Worker build, and copies the HTML into the final assets directory. This avoids Nitro beta's Wrangler preview launcher during Cloudflare prerender (`spawn npx ENOENT` on Windows). Vite preview is forced to 4620 even when TanStack requests an ephemeral build-time port. No Wrangler server is started by either build script. Do not set the internal `LOGBIRD_WEB_STATIC_READY` flag yourself; the wrapper owns the checked handoff.

`_headers` applies CSP, nosniff, referrer policy, HSTS and restricted permissions to assets. Nitro route rules apply equivalent server headers. Hashed assets and `/media/*` get one-year immutable caching. Change a media ID when replacing its source to avoid stale cached content.

The two builds overwrite `.output`; rebuild Node before previewing after Cloudflare. Deploy Cloudflare output, not Node output.

## Verification tools

These tools use an existing server and start none:

```sh
pnpm --filter @logbird/web lighthouse
pnpm --filter @logbird/web lighthouse --no-fail
pnpm --filter @logbird/web capture
pnpm --filter @logbird/web exec tsx scripts/bundle-report.ts
```

- Lighthouse accepts `BASE_URL` (default local port 4620) and `OUT_DIR` (default `.tmp/lighthouse`). It audits all prerender paths on mobile/desktop, prints four scores, writes JSON, fails below 95 unless `--no-fail`, and always kills Chrome. The intentionally noindex blog draft is expected to lose SEO points and remains visible in the audit.
- Capture accepts `BASE_URL`, `OUT_DIR` (default `.tmp/captures`), comma-separated `PATHS` (default all prerender paths) and optional `VIDEO=1`. It captures 1440×900/390×844 in both themes, sets stored theme before loading, and records an eight-second scroll down/back. Console/page errors, failed requests and HTTP failures fail the run. Browser/context close in finally blocks. It uses installed Chrome in a disposable automation context.
- Bundle report totals gzip bytes of scripts/modulepreloads and static dependencies per emitted HTML page and writes `.tmp/bundle-sizes.json`. It excludes CSS/fonts and unrequested dynamic imports.

Also verify each page's HTML heading without JavaScript; the discovery files; `/og/home.png`; an unknown route's HTTP 404; and a unique fictional `@example.test` waitlist submission in JSONL and Mailpit (`http://127.0.0.1:8025/api/v1/messages`). Delete only that matching Mailpit message by ID. Preserve other records/messages. Stop the preview's whole process tree afterwards, confirm port 4620 is free and close all task browsers. Never start other Logbird apps or backing services for this verification.
